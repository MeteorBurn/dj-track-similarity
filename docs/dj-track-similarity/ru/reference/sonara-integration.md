# Интеграция SONARA

> Для кого: Разработчики, проверяющие расчёт и хранение результатов SONARA.
> Задача: Описать декодирование, результаты и границы хранения для установленного пакета.
> Тип: Справочник

## Текущий путь анализа

Текущее окружение проекта использует SONARA `0.3.5` в режиме `playlist` с диапазоном BPM `70..180`.
Задача передаёт упорядоченные партии путей прямо в `sonara.analyze_batch()`. Декодированием владеет
SONARA/Symphonia. Этот путь
не использует общий загрузчик FFmpeg проекта и не переключается на другой декодер при ошибке. ML и
предпросмотр по-прежнему зависят от FFmpeg.

Проект запрашивает только признаки, которые использует текущий код. При обновлении SONARA набор
можно расширить вместе с хранилищем и потребителями. Совместимость при этом определяется нужной
структурой данных.

SONARA `0.3.5` предоставляет необязательный признак `aggression`. Проект пока не запрашивает и не
хранит эти данные. Существующее значение `mood_aggressive_score` приходит из отдельно запрошенного
признака `mood`.

## Результаты

| Результат | Содержимое | Хранилище |
| --- | --- | --- |
| `core` | скалярные и компактные векторные признаки, включая полные Contrast, MFCC и Chroma | Core `sonara` |
| `timeline` | доли, атаки, события аккордов, кривые темпа, энергии и громкости, первые доли такта и сегменты | Artifacts `sonara_timeline` |
| `embedding` | вектор похожести SONARA | Artifacts `sonara_similarity_embeddings` |
| `fingerprint` | аудиоотпечаток | Artifacts `sonara_fingerprints` |

`core` включается по умолчанию. Выбор нескольких результатов выполняет один вызов SONARA, после
чего выбранные части записываются без повторного декодирования. Metrogram `time_signature` не входит
в текущий набор Core: ранжирование и классификаторы его не используют, а Beatgrid применяет
обычное запасное значение SONARA.

## Граница хранения

Каталог состоит из Core и обязательной базы Artifacts с общим `catalog_uuid`. Evaluation —
необязательная третья база, которую создают только сценарии оценки. Обычный запуск проверяет
необходимые таблицы, столбцы, индексы и связь Core с Artifacts. Несовместимый комплект отклоняется с
понятным сообщением и не изменяется автоматически.

Явный маршрут временных данных загружает сохранённый результат `timeline`. Окно метаданных
показывает его сводку, а также наличие embedding и fingerprint. Если нужны полные временные данные,
используйте явный маршрут.

## Обновление SONARA и структуры данных

Обновление пакета SONARA само по себе не запускает миграцию и не удаляет результаты. Если новый
параметр требует новых столбцов или таблиц, сначала адаптируйте код проекта и подготовьте одноразовое
структурное преобразование. Обычный запуск не выполняет его.

Сначала просмотрите план:

```powershell
dj-sim migrate-database --db .\data\library.sqlite --dry-run
```

Если план верен, повторите команду без `--dry-run`. Применение требует точной фразы
`MIGRATE DATABASE`. Команда создаёт и проверяет резервные копии Core и Artifacts, преобразует их как связанную пару и
проверяет целостность, внешние ключи и потерянные ссылки. Повторный анализ не запускается
автоматически: пользователь решает, какие результаты пересчитать после изменения структуры или
набора признаков.

## Граница ранжирования

Поиск, SET, Hybrid и классификаторы читают только нужные им сохранённые признаки. Timeline,
эмбеддинг и отпечаток SONARA могут храниться для отдельных или будущих сценариев. Любой результат —
сигнал ранжирования или диагностики, а не автоматическое решение диджея.
