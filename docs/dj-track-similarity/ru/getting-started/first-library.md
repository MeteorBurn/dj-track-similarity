# Создайте первую фонотеку

> Для кого: Для тех, кто создаёт фонотеку SQLite из папки с музыкой.
> Задача: Понять сканирование, Refresh Tags, просмотр и выбор базы данных.
> Тип: Учебная инструкция

Фонотека — это личная карта вашей музыкальной коллекции внутри приложения. Она позволяет искать
по одному каталогу, даже если файлы разбросаны по разным папкам, а теги заполнены не полностью.
Аудиофайлы остаются на своих местах.

## Что даёт сканирование

- единый список поддерживаемых аудиофайлов для просмотра;
- поиск по исполнителю, названию, альбому, жанру, пути и другим доступным тегам;
- стабильные записи треков, к которым позже привязываются результаты анализа;
- счётчики добавленных, обновлённых, неизменившихся и пропущенных файлов.

Одного сканирования недостаточно для поиска по звучанию. Сначала оно создаёт каталог, а следующий
шаг — [анализ](./first-analysis.md) — добавляет аудиоданные для поиска похожих треков, текстового
поиска, сравнения LAB, Audio Dedup и классификаторов.

## Как хранится каталог

Выбранный файл Core хранит идентичность треков, пути, теги, компактные строки анализа, отметки
«нравится» и оценки классификаторов. Обязательный соседний файл `*.artifacts.sqlite` хранит большие
активные ML-эмбеддинги и зарезервированные таблицы SONARA. У двух файлов должен совпадать `catalog_uuid`; исполняемая
часть проверяет эту связь и требуемые таблицы, столбцы и индексы перед работой.

`*.evaluation.sqlite` — необязательная соседняя база для данных оценки. Она не создаётся при одном
лишь определении пути. Обычный запуск не преобразует несовместимую структуру Core или Artifacts.

## Выберите или создайте базу

В браузере нажмите кнопку базы рядом с полем пути только для чтения и выберите SQLite-файл Core.
Новый путь создаёт пару Core + Artifacts. Существующий путь загружается только после проверки
обязательного файла Artifacts, общего `catalog_uuid` и структурных требований к обеим базам. При
смене базы также очищается старое состояние фонотеки и поиска, поэтому запоздалый ответ не добавит
строки из предыдущего каталога.

В CLI передайте `--db`:

```powershell
dj-sim scan D:\Music --db .\data\library.sqlite
```

## Просканируйте папку

В браузере:

1. Выберите базу данных.
2. Введите **Music root** или воспользуйтесь выбором папки.
3. При необходимости измените **Scan workers**.
4. Нажмите **Load tracks into the database**.

Панель активности показывает очередь и ход задачи сканирования, счётчики, ошибки, отмену и
завершение. После окончания браузер обновляет сводку фонотеки.

Эквивалентная команда CLI:

```powershell
dj-sim scan D:\Music --db .\data\library.sqlite
```

Оба варианта создают новую связанную пару Core + Artifacts, когда отсутствуют оба файла. Для
несовместимой существующей пары используйте явную команду `migrate-database` после просмотра плана
без записи.

Поддерживаемые расширения:

```text
.aif .aiff .alac .flac .m4a .mp3 .ogg .opus .wav .wave
```

Файлы AppleDouble, имена которых начинаются с `._`, пропускаются.

## Что читает сканирование

Через Mutagen читается фиксированный набор полезных человеку метаданных: исполнитель, название,
альбом, жанр, год, страна, лейбл, номер в каталоге, номер трека и диска, BPM, тональность,
комментарии, ISRC, длительность, аудиоформат и данные кодека, если они доступны.

Если теги прочитать не удаётся, приложение всё равно создаёт минимальную запись, используя имя файла
без расширения как название.

## Что записывает сканирование

Сканирование записывает только строки треков и тегов Core. Оно обновляет трек при изменении размера
файла или времени модификации и не записывает аудиотеги.

CLI выводит число добавленных, обновлённых, неизменившихся и пропущенных файлов.

## Refresh Tags

Backend умеет перечитывать теги существующих треков без повторного запуска SONARA, MAEST, MERT,
MuQ или CLAP. Нажмите **Refresh Tags** в панели базы данных, чтобы запустить типизированную задачу
обновления. Она использует текущее значение рабочих потоков сканирования и показывает прогресс в
той же панели активности.

## Просмотр после сканирования

Панель фонотеки получает за один раз одну серверную страницу размером до `200` треков. Переходите
между страницами через **Prev**, **Next** или поле номера страницы. Каждой странице соответствует
один запрос `/api/tracks` с `limit=200`; последняя страница может содержать меньше строк. Все строки
текущей страницы отображаются в одном прокручиваемом списке.

Браузер объединяет строки загруженного результата по `catalog_uuid` и `track_uuid`, сохраняя
наибольший `content_generation`. Подробные метаданные запрашиваются только при открытии;
прослушивание и изменение отметки «нравится» используют ту же точную идентичность трека.
