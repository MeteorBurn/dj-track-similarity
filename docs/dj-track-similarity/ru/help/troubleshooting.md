# Решение проблем по симптомам

> Для кого: Для тех, кто исправляет локальную настройку или анализ.
> Задача: Дать проверки, связанные с текущим хранением и явной миграцией.
> Тип: Помощь

## Сервер сообщает, что FFmpeg не найден

Укажите путь к исполняемому файлу FFmpeg в `DJ_TRACK_SIMILARITY_FFMPEG` или добавьте FFmpeg в `PATH`,
затем перезапустите `dj-sim serve`.

## Выбранная фонотека не открывается

Для фонотеки нужны Core `.sqlite` и обязательный соседний `*.artifacts.sqlite` с одинаковым
`catalog_uuid`. Если сообщение указывает на несовместимую структуру, не редактируйте файлы вручную.
Запустите `dj-sim migrate-database --db <path> --dry-run` и проверьте план.

## Адаптер модели не может загрузить зависимости

Выполните `python -m pip check` в том же активированном окружении, где запускается `dj-sim`, затем
сравните установленный набор с `pyproject.toml` и `uv.lock`. Обновляйте связанные пакеты вместе,
чтобы у адаптера оставались необходимые API, контрольные точки и формы результатов.

```powershell
python -m pip check
```

После изменения окружения перезапустите `dj-sim serve` и все запущенные процессы Rhythm Lab.

## Нет данных Timeline, embedding или fingerprint

Эти результаты находятся в обязательной базе Artifacts, и их нужно запрашивать явно. Core всегда
включён и заблокирован. В панели анализа браузера есть флажки Timeline, embedding и
fingerprint, а в окне метаданных видно наличие каждого необязательного результата. Если нужен не
только признак наличия, а сами временные данные, используйте явный маршрут API.

## Классификатор несовместим

Проверьте, что объявленный артефактом порядок признаков совпадает с текущим рецептом и все входы
есть в базе. При изменившемся рецепте переобучите и опубликуйте профиль. Расчёт классификатора
работает только с базой и ограничен своим `classifier_key`.

## CUDA была запрошена, но анализ завершается ошибкой

Запустите `dj-sim doctor`, затем попробуйте `--device cpu`, чтобы отделить настройку устройства от
самого сценария анализа.
