# Безопасное обслуживание фонотеки

> Для кого: Для тех, кто поддерживает локальное музыкальное состояние в порядке.
> Задача: Обслуживать комплект баз, не изменяя исходное аудио.
> Тип: Сценарий

1. Сканируйте после добавления файлов. Сканирование обновляет треки и теги Core, не записывая аудио.
2. Храните Core и обязательный `*.artifacts.sqlite` вместе: они связаны `catalog_uuid`.
3. Считайте `*.evaluation.sqlite` необязательным состоянием оценки.
4. Перед применением переноса выполните предварительную проверку. Применение меняет только
   сохранённый `tracks.file_path`; файлы не перемещаются, не копируются, не удаляются и не получают
   новые теги.
5. Запускайте Audio Doctor и Audio Dedup в режиме отчёта до режимов применения с подтверждением.

При изменении структуры базы сначала просмотрите план команды
`dj-sim migrate-database --db <path> --dry-run`. Применяйте его только после проверки: точное
подтверждение `MIGRATE DATABASE` создаёт проверенные резервные копии Core и Artifacts перед
перестроением. Повторный анализ и переобучение классификаторов остаются отдельными решениями.

Запускайте `python scripts\optimize_database.py --db .\data\library.sqlite` только для локального
набора файлов под вашим контролем. Скрипт проверяет и копирует Core + Artifacts до обслуживания.
Браузер поддерживает сканирование, Refresh Tags, предварительную проверку переноса и задачи
вспомогательных инструментов в режиме отчёта; оптимизация базы остаётся явным сценарием скрипта.
