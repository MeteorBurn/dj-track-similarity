# Audio Dedup

> Для кого: Пользователи, которые ищут возможные дубликаты аудио.
> Задача: Безопасно создать отчёт и понимать режим применения.
> Тип: Руководство

По умолчанию Audio Dedup читает существующую библиотеку SQLite и создаёт отчёты JSON, XLSX и журнал.
Он использует сохранённый анализ и локальные пути, не сканируя неизвестные папки за пределами
выбранного корня.

## Требования

Инструменту нужны сохранённые данные аудио–аудио. Доступны источники эмбеддингов `mert`, `maest`,
`muq` и `clap`. Загрузчик принимает только структурно совместимые векторы для текущей идентичности
и поколения трека.

Значение `min_similarity` задаёт порог содержимого аудио–аудио. Это не шкала текстового поиска CLAP, и ни одно
из этих значений не является вероятностью.

## Источники и веса

Профиль CLI и API по умолчанию включает все четыре источника эмбеддингов:

| Источник | Исходный вес |
| --- | ---: |
| MERT | 0.43 |
| MAEST | 0.32 |
| MuQ | 0.12 |
| CLAP | 0.04 |

Исходные веса — это коэффициенты конфигурации, а не проценты. Оценка делится на сумму весов включённых данных,
которые доступны для конкретной пары. Оценка дубликата также может учитывать сохранённые данные SONARA и длительность.

CLI принимает повторяемые параметры `--source` и `--weight FAMILY=VALUE`. API `POST /api/audio-dedup/jobs`
принимает эквивалентные поля `sources` и `weights`.

Проверка конфигурации закрывается при ошибке:

- `sources` должен быть непустым, содержать уникальные значения и только четыре поддерживаемых семейства.
- Если задан `weights`, его ключи должны в точности совпадать с включёнными источниками.
- Каждый вес должен быть конечным и неотрицательным, причём хотя бы один вес должен быть положительным.

Чтобы отключить MuQ и точно воспроизвести прежний профиль источников, выберите только MERT, MAEST и CLAP.
Если не задавать веса явно, эти источники получат прежние исходные веса:

```powershell
python tools\audio-dedup\audio_dedup_cli.py --db .\data\library.sqlite --root D:\Music `
  --source mert --source maest --source clap
```

В этом точном профиле используются веса MERT 0.43, MAEST 0.32 и CLAP 0.04. Для любой другой конфигурации
источников или весов действуют описанные ниже правила безопасного удаления для нового профиля.

## Работа в интерфейсе

Откройте Audio Dedup значком копирования в верхней панели.

Диалог браузера предоставляет те же поля `sources` и `weights`, что CLI и API:

- флажки включают или исключают MERT, MAEST, MuQ и audio-to-audio CLAP;
- **Custom raw weights** показывает поле исходного веса для каждого включённого источника;
- **Reset defaults** возвращает четыре источника с исходными весами 0.43, 0.32, 0.12 и 0.04;
- **Pre-MuQ legacy** выбирает только MERT, MAEST и CLAP с исходными весами 0.43, 0.32 и 0.04.

Хотя бы один источник должен оставаться включённым. Отключённые источники не попадают в payload.
Панель выполнения показывает фактические источники и исходные веса из ответа задачи, поэтому
отправленная конфигурация остаётся видимой во время и после работы.

Настройки:

- **Root**: рассматриваются только треки базы внутри этого сохранённого корневого пути.
- **Path contains**: необязательные регистронезависимые фильтры пути, разделённые строками, запятыми или точками с запятой.
- **Preset**: safe, balanced или aggressive.
- **Min score**: необязательное переопределение `0..1`.
- **Min similarity**: необязательный порог аудио–аудио `0..1` по включённым источникам эмбеддингов.
- **Limit groups**: необязательное максимальное число групп.
- **Output dir**: каталог отчётов.

Нажмите **Start**, чтобы создать отчёт. Интерфейс покажет ход работы и по завершении откроет XLSX.
Флажок **Apply delete safe candidates** показывает поле подтверждения; браузер не отправит режим
применения, пока в нём нет точного текста `APPLY DELETE`.

## Отчёт из CLI

```powershell
python tools\audio-dedup\audio_dedup_cli.py --db .\data\library.sqlite --root D:\Music --preset safe
```

Дополнительный пример:

```powershell
python tools\audio-dedup\audio_dedup_cli.py --db .\data\library.sqlite --root D:\Music --path-contains wav --limit-groups 50
```

Явно заданный профиль источников по умолчанию выглядит так:

```powershell
python tools\audio-dedup\audio_dedup_cli.py --db .\data\library.sqlite --root D:\Music `
  --source mert --source maest --source muq --source clap `
  --weight mert=0.43 --weight maest=0.32 --weight muq=0.12 --weight clap=0.04
```

## Подтверждение для безопасного удаления

MuQ и CLAP могут влиять на ранжирование и кандидатов в отчёте, но не могут заменить MERT вместе с MAEST
при автоматическом удалении.

Точный прежний профиль сохраняет прежний общий порог. Для любой другой конфигурации источников или весов нужны:

- текущие данные MERT и MAEST для пары;
- положительный вес MERT и положительный вес MAEST;
- независимая взвешенная схожесть MERT и MAEST, которая достигает заданного пресетом `min_similarity`;
- существующая проверка совместимости длительности.

Высокая схожесть только по MuQ или CLAP может создать кандидата для ручной проверки, но не кандидата для
безопасного удаления.

## Режим применения

Применение разрушительно и требует точного подтверждения:

```text
APPLY DELETE
```

Инструмент удаляет только безопасных кандидатов внутри выбранного `--root`. Перед удалением он повторно проверяет
поля идентичности отчёта `catalog_uuid`, `track_uuid` и `content_generation`, сохранённый путь, а также указанные
в отчёте `size` и `file_modified_ns`. Устаревшие или несовместимые кандидаты пропускаются.

Из SQLite удаляются только те треки, чьи файлы действительно были удалены.

Не запускайте применение в обычных тестах. Сначала изучите отчёт, а для важной библиотеки сохраните
резервные копии.

## Выходные данные

По умолчанию отчёты JSON, XLSX и журнал создаются под `tools/audio-dedup/data/reports/`. В JSON сохраняются
поля `sources` и `weights`. Данные по парам и листы кандидатов/доказательств XLSX содержат `muq_similarity`,
а причины запрета записываются в `blocked_reasons`.

Это личные локальные артефакты.
